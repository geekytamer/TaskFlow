# Meta M1 (connected accounts, verified stats) and M2 (proof of delivery) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Influencers connect Instagram accounts; their figures sync daily and show as verified to clients; a published deliverable gets its real results (views, likes, comments, saves, shares) at 24 hours, 7 days and 30 days, which clients see as proof of delivery.

**Architecture:** A `backend/src/social/` module behind a `MetaClient` interface. Production uses `HttpMetaClient` (Instagram API with Instagram Login, Graph API v26); tests and local development use `FixtureMetaClient` with recorded JSON. Tokens are encrypted with AES-256-GCM under a key id so keys rotate. Sync and result checkpoints run in the existing hourly sweep for now (a separate worker process comes with webhooks in M3). The portal reads only stored snapshots, never Meta live.

**Tech Stack:** Express, better-sqlite3, Node `crypto`, node:test + supertest; Next 15 portal; TaskFlow staff frontend.

**Deviation from the skill template (deliberate):** tasks fix interfaces and tests, not implementation code. Project principle 2: an earlier plan that pre-wrote ~3,000 lines drifted from the real files. Code is written test-first at execution time.

## Global Constraints

- Store `views`, never `impressions`/`plays` (deprecated April 2025); Graph API v26.
- Scopes requested: `instagram_business_basic`, `instagram_business_manage_insights` only.
- Only Business/Creator accounts can connect; a personal account gets a clear message.
- Secrecy rules unchanged: no rates, costs or margins anywhere new; influencers see no benchmarks.
- No live Meta call in any test. Production refuses to start the social module without `SOCIAL_TOKEN_KEYS`.
- Additive only: new tables, new files; shared files touched only to wire things in.
- Bilingual (en/ar), phones first, 44px touch targets (iteration-3 rules).

### Task 2: MetaClient and fixtures

interface MetaClient {
  authorizeUrl(state: string, redirectUri: string): string;

### Task 4: Connect, callback, disconnect, deletion

Routes (influencer audience): `POST /influencer/social/instagram/connect` → `{ url }` (state bound to session); `GET /social/instagram/callback?code&state` (public, state-checked) → stores the account, runs a first sync, redirects to the portal profile; `POST /influencer/social/:id/disconnect` → status `revoked`, token erased, snapshots kept for 30 days then purged; `POST /social/meta/data-deletion` (signed request verified with the app secret) → purges the account and returns Meta's `{ url, confirmation_code }`.

- [ ] Tests: a personal account is refused with a message; another influencer's state or account id is 404; a reused or expired state is 400; the token is never in any response; the deletion callback rejects a bad signature and purges on a good one.
- [ ] Implement, pass, mutation-check the state binding and token secrecy, commit.

### Task 5: Daily sync and verified stats

`syncAccount(store, client, account)`: refresh tokens expiring within 7 days; write today's snapshot; on `MetaAuthError` set `needs_reconnect` and notify the contact owner once. Contact figures for the catalogue come from the latest snapshot when an active connection exists (`verified: true`, `asOf`), otherwise from staff-entered numbers (`verified: false`).

- [ ] Tests: snapshot written once per day; auth error flips status and notifies once; catalogue DTO shows `verified` + `asOf` and keeps all secrecy fixtures passing; influencer profile shows connection status but no token.
- [ ] Implement, pass, commit.

### Task 6: Proof of delivery (M2)

When a deliverable is `Published` with a post URL from a connected account, the sweep resolves the media id once, then stores checkpoints at 24h, 7d, 30d after `publishedAt`. Client campaign detail gains `results` per deliverable (latest checkpoint, `verified`), and the campaign gets totals.

- [ ] Tests: checkpoints written at the right times only once; a post from an unconnected account yields `results: null` (no guessing); client sees results only for their own campaign; influencer sees their own results.
- [ ] Implement, pass, commit.
